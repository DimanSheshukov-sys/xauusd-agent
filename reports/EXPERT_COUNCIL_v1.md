# СОВЕТ СПЕЦИАЛИСТОВ v1 — аудит сайта и системы XAUUSD Elliott Agent

Дата: 2026-09-16 · Формат: независимые заключения семи ролей → консолидированная дорожная карта.
Основание: живые замеры сайта, чтение кода (`engine/`, `web/`, `trade_journal.py`, `learn.py`),
отчёты (`EXPERIMENT_v2/v3`, `WALKFORWARD_v2`, `LEARNING_v1`, `TRADE_JOURNAL`), freeze v2 + addenda.

**Замеренные факты, на которые опирается совет:**
- первая загрузка live-страницы ≈ **76 КБ** (html 28.7 + magic.css 10.9 + live_engine 12.3 + paper 10.8);
- live-тик каждые 10 c дёргает **8 эндпоинтов** (4 ТФ + 3 агрегата + спот) = **48 запросов/мин** с одной вкладки;
- латентность источников: Binance 136 мс, gold-api **683 мс** (и только цена, без bid/ask);
- спред XAUUSD, замеренный в разных сессиях: **0.40 / 0.46 / 0.50 / 0.62 / 0.83 USD** (разброс 2×);
- forward OOS: **0 сделок** (режим BEAR, WAIT по §7); база: N=163, WR 60.1%, Exp +0.156R (PROXY);
- walk-forward: сделки только в **4 из 14** фолдов (порог eligibility N≥25);
- шум базиса PAXG↔GC=F ≈ **2 × ATR(M15)**.

## 1. Quant-методолог (статистика и валидация)

| # | Находка | Почему важно | Рекомендация | Приоритет |
|---|---|---|---|---|
| Q1 | Live-доказательств пока нет (N=0); всеwin rate'ы — из PROXY-бэктеста | любой вывод о «рабочести» преждевременен | копить forward до N≥74; добавить **always-valid p-value** (sequential testing), чтобы смотреть в журнал без peeking-bias | P0 |
| Q2 | WF-оценка держится на 4 фолдах бычьего режима 2025–2026 | оценка не репрезентативна для боковика/медвежья | режимно-стратифицированный WF или явная пометка мощности каждого фолда | P1 |
| Q3 | Множественные сравнения (геометрии × ветки × степени) | лучшие цифры — частично selection artifact | зафиксировать **primary endpoint** (expectancy net на forward) и семейство тестов; H-MTF-ALIGN уже pre-registered — это правильно | P1 |
| Q4 | Мёртвые ветки (SHORT, W3-A) продолжают жить в документах как «активные» | путает читателя и будущие прогоны | ввести **реестр жизненного цикла веток**: research → candidate → active → retired, с датами и причиной | P2 |
| Q5 | Нет доверительных интервалов в журнале | «60 из 100» без интервала читается как точность | показывать 95% CI для WR и expectancy в human-версии журнала | P2 |

## 2. Риск-менеджер

| # | Находка | Почему важно | Рекомендация | Приоритет |
|---|---|---|---|---|
| R1 | В paper-режиме нет аварийных ограничителей | серия стопов может съесть депозит даже в симуляции, формируя ложную уверенность | **circuit breaker**: дневной лимит −3R → автопауза до следующего дня + баннер; максимум 1 позиция (уже так) | P0 |
| R2 | Издержки в модели — константа 0.40 USD при наблюдаемом разбросе до 0.83 | при 0.83 cost/R ≈ 0.06 > лимита G14a 0.05 → гейт должен был бы блокировать, но не знает об этом | **динамический спред** (Binance depth/TV WSS) + консервативный fallback 0.60; G14a считать по живому спреду | P0 |
| R3 | R не привязан к капиталу: журнал только в R | невозможно оценить реальную кривую капитала и риск разорения | задать риск на сделку (например 0.5% капитала), показать equity в % и в деньгах, стресс-тест серии из 10 стопов | P1 |
| R4 | Нет модели.slippage для стоп-выходов (гэпы) | реальный стоп исполнится хуже уровня | чувствительность: slippage 0.1/0.2/0.3 USD на стоп-выходах в бэктесте | P1 |
| R5 | Гэпы золота на выходных/сессиях CME | SL может улететь далеко за уровень | отчёт «gap sensitivity»: распределение гэпов open-vs-prev-close на D1 | P2 |

## Консенсус совета (единогласно)

1. **Не повышать статус ни одной ветки**, пока forward N < 74; текущие «60 из 100» публиковать только с пометкой PROXY и CI.
2. **До любого live-использования** (даже paper) внедрить пункты 1–2: издержки по живому спреду и дневной аварийный лимит.
3. **Не добавлять новые сигнальные правила** (включая H-MTF-ALIGN) до завершения их pre-registered валидации.
4. Красоту и доступность улучшать только после пунктов P0–P1 безопасности и методологии.

## Чего совет делать НЕ рекомендует

* добавлять индикаторы «для подтверждения» (нарушает structure-first и множит сравнения);
* усреднять/смещать стоп вручную («дать сделке подышать»);
* считать win rate по paper-журналу без учёта издержек и CI;
* публиковать результаты без пометок PROXY / in-sample / forward;
* калибровать что-либо по final OOS (§64 канона).
